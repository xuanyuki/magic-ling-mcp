# 宿主接入方案

## 推荐的第一版

维护一个与游戏源码分开的 `magic-ling-plugin` 工程，并在自己的游戏构建中把它作为独立模块依赖。插件只提供：

1. `MyriadCodexModel`：把完整百科条目和本杖击杀类名合并成稳定、有序的行。
2. `ReflectiveStaffKillSource`：读取 0.9.6.5 法杖实例的 `killedTypes`。
3. `ReflectiveBestiaryCatalogSource`：读取游戏公开的 `Bestiary.entities/isSeen/encounterCount`。
4. `CodexWindowPresenter`：由宿主负责用游戏自己的 UI 打开窗口。

宿主窗口可复用 `WndJournal` 的 `ScrollingGridPane`、`WndJournalItem`、`Mob.sprite()`、`Mob.name()` 和 `Mob.description()`。每个格子增加一个状态标识即可：

- 绿色/勾：`KILLED_BY_STAFF`
- 灰色/空心：`NOT_KILLED_BY_STAFF`
- 黄色/问号：`UNMAPPED_KILL`

窗口标题显示 `本杖已击杀 X / 全部 Y`，格子颜色区分已击杀、未击杀和未映射记录；筛选按钮可以在宿主 UI 接入时继续增加。点击格子继续打开现有 `WndJournalItem`，不修改战斗逻辑。

## 最小宿主入口

源码构建中只需要一个明确的接入点，示意如下（此处是宿主侧代码，不写回本地解包目录）：

```java
// 在查看 StaffofMyriadThings 的 WndUseItem/物品详情动作中：
MyriadPlugin plugin = ...; // 初始化一次
plugin.openFor(staff, model -> GameScene.show(new WndMyriadCodex(model)));
```

`WndMyriadCodex` 属于宿主 UI 适配层，可以作为 `:myriad-mod-host` 源集单独维护；它不需要改动 `WndJournal` 的原有百科页面。插件初始化可以保持显式：

```java
MyriadPlugin plugin = new MyriadPlugin(new MyriadCodexService(
        new ReflectiveStaffKillSource(),
        new ReflectiveBestiaryCatalogSource()));
```

为了让升级可检测，宿主最好给法杖加一个只读方法：

```java
public Set<String> killedTypesSnapshot() {
    return Collections.unmodifiableSet(new HashSet<>(killedTypes));
}
```

如果不希望改动宿主类，当前插件的反射适配器可以工作，但字段名或 Android R8 处理变化后应显示“不兼容”而不是显示空列表。

## 现有二进制的限制

0.9.6.5 的启动器没有外置 JAR 扫描或 mod loader。把 `myriad-plugin.jar` 放在游戏目录或 APK 同级不会触发任何代码。桌面端可以实验性地写一个自定义 Bootstrap/Java Agent，在 `-cp` 或 `-javaagent` 启动时接入；这条路线依赖类路径、字节码布局和启动参数，不能作为 Android 方案。Android 需要重新构建 APK（并重新签名），因此跨端发布应采用源码构建版。

## 不修改解包目录的构建流程

1. 将上游 `0.9.6.5` 源码检出到临时只读目录，或通过 Gradle 依赖使用其源码构建。
2. 把本工程作为独立模块加入自己的构建工作区；不要把文件复制到 `魔绫地牢-V0.9.6.5_extracted` 或 `移动端_extracted`。
3. 先运行纯 Java 模型测试，再运行宿主端编译和桌面/Android smoke test。
4. 将输出写到 `magic-ling-plugin/dist/`；原始 JAR/APK 保持原 SHA-256。

## 兼容性检查

插件启动或第一次打开窗口时应检查：

- 法杖类名是否完全匹配 `StaffofMyriadThings`。
- `killedTypes` 是否为 `Set<String>`。
- `Bestiary` 是否提供 `entities()`, `isSeen(Class)`, `encounterCount(Class)`。
- 游戏版本/构建号是否为 `0.9.6.5 / 2026100600`。

任一检查失败都应该给出可读的“不兼容版本”提示，并保留游戏原本的物品详情行为。
