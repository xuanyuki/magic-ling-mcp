# 宿主接入与运行方式

## PC 外置 Agent

`MyriadAgent` 的 `premain` 为 0.9.6.5 的 `WndUseItem(Window, Item)` 构造器添加退出 Advice。它只对 `StaffofMyriadThings` 实例添加按钮，并由 `MyriadCodexButton` 在用户点击后打开图鉴。原游戏 JAR 只作为 Agent 编译时 API 和运行时主程序使用，所有新类与 Byte Buddy 位于外置 Agent JAR。

可从一开始启动 Agent：

```text
java -javaagent:myriad-codex-agent.jar -jar 魔绫地牢-V0.9.6.5.jar
```

这不会修改安装包文件，但游戏进程中的类定义和 UI 会被运行时注入逻辑改变。当前开发版按 `0.9.6.5 / 2026100600` 锁定。

也可以在游戏启动后通过 JDK Attach API 注入：

```powershell
.\magic-ling-plugin\attach-agent.ps1 -ProcessId <游戏 Java 进程 PID>
```

Attach 后要重新打开法杖详情窗口，让新建的 `WndUseItem` 经由注入点。目标进程需允许动态附加，且注入工具要有相同用户权限；如果游戏用的 JVM 不兼容 Attach，就通过 `run-with-agent.bat` 启动。

## Android

Android Activity 启动没有 Java `-javaagent` 参数。普通应用受 sandbox 限制，不能自行注入另一应用。不过 ADB shell 有面向调试的 `am attach-agent <PROCESS> <FILE>` 命令，Android 14 的 Activity Manager 会对目标应用执行 debuggable 检查；静态分析报告显示此 APK 的 manifest 设置 `debuggable=true`。因此可以尝试将按目标 ABI 构建的原生 JVMTI `.so` 放入应用可读路径后，通过 USB 调试挂到现有进程，保持 APK 字节不变且未必需要 root。

这还不是已完成方案：需要确认目标设备 Android 版本是否提供该命令、`run-as`/ADB 权限和目标进程状态，并实现原生 JVMTI Agent 与游戏 Java UI 的桥接。本项目当前没有 Android `.so`，没有在实体设备验证。若 shell attach 不可用，再评估 root 级 Zygisk/LSPosed 或源码构建。
